# Intake Form

Fields captured for every candidate workflow submitted to [Loop 1: Intake](01-intake.md). Source:
[`content/ai-skills-and-ai-coe-ultimate-guide.md`](../content/ai-skills-and-ai-coe-ultimate-guide.md),
"AI CoE Operating Model for Skills → 1. Intake".

| Field | What it captures |
|---|---|
| Workflow name | A short, specific name for the candidate workflow |
| Business owner | Who is accountable for this workflow existing and working |
| User group | Who will actually run this Skill day to day |
| Frequency | How often the workflow happens (daily, weekly, per-event) |
| Pain level | How bad the current manual version is |
| Current manual process | What people do today without the Skill |
| Required systems | What tools, APIs, or data sources the workflow touches |
| Data sensitivity | What tier the data involved sits at (see [`../governance/trust-tiers.md`](../governance/trust-tiers.md)) |
| Expected business value | Why this is worth CoE time relative to other candidates |
| Failure risk | What happens if the Skill gets it wrong |
| Human approval needs | Where a human must stay in the loop, and why |

Do not approve a candidate because it sounds interesting. Prioritize workflows that are frequent,
painful, valuable, and teachable — a workflow nobody can explain clearly will encode confusion
instead of removing it.
